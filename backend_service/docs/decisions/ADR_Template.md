## 使用说明

### 如何创建ADR

1. **复制模板**: 复制此模板创建新的ADR文档
2. **编号规则**: 使用递增的4位数字编号 (如ADR-0001)
3. **文件命名**: 使用格式 `ADR-XXXX-简短描述.md`
4. **状态管理**: 及时更新决策状态
5. **评审流程**: 重要决策需要团队评审

### ADR状态说明

- **提议中**: 决策正在讨论和评估中
- **已接受**: 决策已被接受并开始实施
- **已弃用**: 决策已被放弃，不再使用
- **已替代**: 决策被新的决策替代

### 最佳实践

1. **及时记录**: 在做出重要技术决策时及时创建ADR
2. **详细描述**: 提供足够的背景信息和决策理由
3. **定期回顾**: 定期回顾ADR的有效性和实施效果
4. **团队共识**: 确保团队成员理解和认同决策
5. **持续更新**: 根据实施情况更新ADR内容

### 决策类型示例

- 技术栈选择 (编程语言、框架、数据库等)
- 架构模式选择 (微服务、单体、事件驱动等)
- 工具选择 (CI/CD工具、监控工具、开发工具等)
- 设计模式选择 (设计模式、编码规范等)
- 基础设施选择 (云服务、部署方式等)
