<execution>
  <constraint>
    ## 项目技术约束
    - **框架约束**：必须使用FastAPI 0.104.1，不可更换为Django或Flask
    - **架构约束**：严格遵循Clean Architecture + DDD模式，不可违反依赖倒置原则
    - **数据库约束**：PostgreSQL 15+，必须支持JSONB字段存储配置数据
    - **Python版本**：Python 3.12+，必须使用类型注解和async/await语法
    - **多租户约束**：所有数据模型必须包含tenant_id字段，确保数据隔离
    - **性能约束**：API响应时间必须<200ms，支持1000+并发用户
    - **兼容性约束**：必须与现有28个API端点保持向后兼容
  </constraint>

  <rule>
    ## 开发强制规则
    - **代码质量强制**：所有代码必须通过mypy类型检查，black格式化，flake8语法检查
    - **测试覆盖率强制**：新增代码测试覆盖率必须>80%，核心业务逻辑必须>95%
    - **API规范强制**：所有API必须使用OpenAPI 3.0规范，自动生成文档
    - **异步优先强制**：数据库操作、文件操作、HTTP请求必须使用异步方式
    - **安全规则强制**：所有API必须验证JWT Token，敏感数据必须加密存储
    - **多租户强制**：所有数据访问必须基于tenant_id过滤，禁止跨租户数据访问
    - **配置驱动强制**：业务逻辑必须通过配置引擎驱动，禁止硬编码业务规则
    - **错误处理强制**：必须使用结构化异常处理，返回标准化错误响应
  </rule>

  <guideline>
    ## 开发指导原则
    - **优雅代码原则**：追求简洁、可读、可维护的代码风格
    - **性能优先原则**：在保证功能的前提下，优先考虑性能优化
    - **渐进式开发**：采用增量开发方式，确保每个迭代都可用
    - **文档同步原则**：代码变更必须同步更新API文档和技术文档
    - **团队协作原则**：代码风格统一，接口设计协商一致
    - **可观测性原则**：关键业务流程必须有完善的日志和监控
    - **扩展性考虑**：设计时考虑未来扩展需求，避免过度耦合
  </guideline>

  <process>
    ## 完整开发流程

    ### Phase 1: 需求分析与设计 (Design First)
    ```
    1. 业务需求分析
       - 理解PRD文档中的功能需求
       - 识别新增角色（门岗、前台、部门负责人）的具体职责
       - 分析四大核心场景的技术实现路径
    
    2. API设计优先
       - 设计OpenAPI 3.0规范的API接口
       - 定义请求/响应的Pydantic模型
       - 确定HTTP状态码和错误处理策略
       - 与前端团队确认接口契约
    
    3. 数据模型设计
       - 基于DDD原则设计领域实体
       - 设计SQLAlchemy模型和数据库表结构
       - 制定数据迁移脚本（Alembic）
       - 设计JSONB配置字段结构
    ```

    ### Phase 2: 领域层开发 (Domain First)
    ```
    1. 实体和值对象开发
       - 实现核心业务实体（Visitor, Employee, Site等）
       - 开发值对象和枚举类型
       - 实现领域服务和业务规则
    
    2. 领域事件设计
       - 设计访客状态变更事件
       - 实现工作流状态事件
       - 配置变更事件处理
    
    3. 领域异常设计
       - 定义业务异常类型
       - 实现异常层次结构
       - 错误码标准化
    ```

    ### Phase 3: 应用层开发 (Service Layer)
    ```
    1. DTO和接口定义
       - 实现数据传输对象（DTOs）
       - 定义仓储接口和服务接口
       - 设计依赖注入契约
    
    2. 应用服务开发
       - 实现业务用例服务
       - 配置引擎服务开发
       - 工作流引擎服务实现
       - 场景路由服务开发
    
    3. 任务和通知
       - Celery异步任务开发
       - 邮件通知服务
       - 第三方服务集成
    ```

    ### Phase 4: 基础设施层开发 (Infrastructure)
    ```
    1. 数据库层实现
       - SQLAlchemy模型实现
       - 仓储模式实现
       - 数据库连接池配置
       - 查询优化和索引设计
    
    2. 缓存层实现
       - Redis缓存策略
       - 缓存键设计和过期策略
       - 缓存穿透保护
    
    3. 外部服务适配
       - 第三方API集成
       - 设备接口适配器
       - 文件存储服务
    ```

    ### Phase 5: API层开发 (Interface Layer)
    ```
    1. FastAPI路由实现
       - 实现API路由处理器
       - 依赖注入配置
       - 中间件配置（认证、CORS、限流）
    
    2. 文档和测试
       - OpenAPI文档优化
       - 自动化测试编写
       - 集成测试实现
       - 性能测试验证
    
    3. 部署和监控
       - Docker容器化配置
       - 环境变量配置
       - 日志配置和监控集成
    ```

    ### Phase 6: 质量保证和优化
    ```
    1. 代码质量检查
       - mypy类型检查
       - black代码格式化
       - flake8语法检查
       - pytest测试运行
    
    2. 性能优化
       - 数据库查询优化
       - API响应时间测试
       - 内存使用优化
       - 并发性能测试
    
    3. 安全检查
       - 依赖漏洞扫描
       - SQL注入测试
       - 权限控制验证
       - 敏感数据加密检查
    ```
  </process>
